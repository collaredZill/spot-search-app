# 周辺スポット検索アプリケーション

指定した現在位置の座標（地図の中心点）および検索半径から、条件に合致する周辺スポットを検索・表示するWebアプリケーションです。

---

## 環境構築

### 必須要件
* Docker 20.10 以上
* Docker Compose v2 以上

---

## 実行手順

1. **コンテナの起動**
   プロジェクトのルートディレクトリで以下のコマンドを実行してください。

```bash
docker-compose up --build
```

2. **動作確認**
   コンテナ起動完了後、以下のURLにアクセスして動作をご確認いただけます。

   * **フロントエンド:** [http://localhost:3000](http://localhost:3000)
   * **バックエンドAPI:** [http://localhost:3001](http://localhost:3001)

---

## 使用した主要技術・ライブラリとその選定理由

### フロントエンド
* **Framework:** Next.js (App Router)
* **CSS Framework:** Tailwind CSS
* **Language:** TypeScript
* **Map Library:** MapLibre GL JS (`maplibre-gl`)
  * 地図描画、マーカー表示、中心ピンの制御用に採用。
  * GoogleGeminiに作らせているので選定理由はわからないが動作的には問題なかったので採用。
* **Geocoding:** OpenStreetMap Tile / Nominatim API
  * 地図タイルの表示および中心座標からの逆ジオコーディング（住所特定）用に採用。
  * フリーで使えるAPIなので採用。

### バックエンド / データベース
* **Framework:** NestJS
* **ORM:** TypeORM
* **Database:** PostgreSQL (PostGIS 拡張機能を使用)
  * 緯度経度に基づく半径検索（空間検索）を高速かつ確実に処理するためにPostGISを有効化。
  * GoogleGeminiが奨めてきた、悪くないので採用。
* **Language:** TypeScript

## 実装時に特に工夫した点、および技術的な判断を行った箇所

* **エラーハンドリングとデバッグ**
  * 開発過程で発生した型定義のエラーや非同期処理・API通信エラーに対し、コンソールログや描画イベント（`load` や `moveend`）のタイミングを細かく分析しながら一つひとつ問題に対処し、安定して動作する状態まで仕上げました。
* **ユーザー体験（UX）への配慮**
  * 地図の中心位置を視覚的に把握しやすくするため、画面中央にCSSマーカーを配置しました。また、地図のドラッグ操作が終わった段階で逆ジオコーディングAPIを呼び出す（`moveend`イベント）ことで、不要なAPI呼び出しを最小限に抑えつつ、中心地点の住所を正確に表示できるよう実装しました。

## 時間が足りず実装を簡略化した箇所や、今後の改善点

1. **コンポーネントの分割・リファクタリング**
   * 現在はプロトタイプとして `Map.tsx` 1ファイル内にUI表示と地図制御のロジックが集約しており、ファイルサイズが大きくなっています。今後は `MapCanvas`（地図描画）、`SearchPanel`（検索UI）、`SpotList`（一覧表示）などにコンポーネントを分割し、可読性と保守性を向上させる予定です。
2. **地図上への検索半径（円）の視覚化**
   * 現在は選択した半径の数値（km）のみを表示していますが、ユーザーが直感的に検索範囲を把握できるよう、地図上に指定半径の円ポリゴンを表示する機能を組み込みたいと考えています。
3. **大量データ（数万〜十万件規模）に対する絞り込み最適化**
   * 今回は検証用データが約200件と小規模だったため単純な全件スキャン・全件検索で対応していますが、本番運用等でスポット数が10万件規模に拡大する場合は、データベース側の空間インデックス（Spatial Index / GiST）の活用に加え、画面内のグリッド/チャンク分割やクラスタリング（GeoJSONのクラスタリング描画）を用いた絞り込み実装が必要になると考えています。
